# NyanLink 双人联机配置清单

日期：2026-10-04（最后更新）　　服务端：`isakio.cn:20100`

换 mod 版本、换服务器、或者朋友重装游戏之后，照着这份走一遍即可。

> **这份是"连现成大厅"的流程**，大厅用 `http://isakio.cn:20100`（我们自己的服务器）。
> 想自己搭一个大厅给自己/朋友用，见 [`nyanlinkd/README.md`](../nyanlinkd/README.md)，
> 一条命令就能装好，然后把这边的地址换成你自己的即可。

## 一、两个人必须完全一致的东西

| 项目 | 要求 | 怎么核对 |
| --- | --- | --- |
| 游戏本体 | 同一个版本（SDEZ 1.70） | 开游戏看标题界面版本号 |
| 曲库 / option 包 | 一致 | 至少招募用的那首歌两边都要有 |
| MelonLoader | 0.6.4 | 日志头 `MelonLoader v0.6.4` |
| WorldLink.dll | **必须是同一个文件** | 大小 50176 字节，md5 `9dfa62d5cba41deac0c2c74334ef8371` |
| InStoreMatch.dll | **两边都要装**（见「二之二」） | 日志出现 `[InStoreMatch] v2.5 已加载`（两边用同一份文件最稳） |
| WorldLink.toml | 内容完全相同 | `LobbyUrl` 必须是 `http://isakio.cn:20100` |

> 历史上出过的坑：一边用上游 MewoLab 的构建（51712 字节，日志前缀 `[WorldLink]`），
> 一边用 NyanLink 分支的构建（50176 字节，日志前缀 `[NyanLink]`），结果就是
> **招募弹窗能看到、但房间进不去**。两边必须统一成 NyanLink 这份。

## 一之二、AquaMai 里必须关掉的选项

AquaMai 的 `[GameSettings.ForceAsServer]` 是**默认开启**的，它会强制
`IsLanAvailable = false`（假装自己是店内服务器、没有局域网），而 NyanLink 的 mod
要强制 `IsLanAvailable = true`。两个补丁打同一个属性会互相打架，结果是游戏认为
"不在店内"，**选曲界面里的「店内マッチング」分类根本不显示，自然就找不到加入入口**。

AquaMai 自己就写着：「如果要配置店内招募的话，应该要把这个关闭」。

改法（注意：这个栏目默认开启，**注释掉是没用的**，必须显式写 `Disabled = true`）：

```toml
[GameSettings.ForceAsServer]
Disabled = true
```

改完要**重启游戏**。位置在游戏根目录的 `AquaMai.toml`，搜 `ForceAsServer` 就能找到。

## 二、每个人要放的文件

都在游戏根目录（`Sinmai.exe` 所在的那层，也叫做 `Package`）：

```
<游戏根目录>\
├── Sinmai.exe
├── Mods\
│   ├── AquaMai.dll
│   ├── WorldLink.dll        ← 1. NyanLink 的客户端 mod（从官方 release 下）
│   └── InStoreMatch.dll     ← 2. 本仓库的修复插件（见「二之二」）
└── WorldLink.toml           ← 3. 放游戏根目录（不是 Mods 里）
```

`WorldLink.toml` 内容（就这几行；`Debug=true` 会往日志里打很多联机调试信息，
排错时方便，平时可以设 false）：

```toml
LobbyUrl="http://isakio.cn:20100"
Debug=false
```

## 二之二、★ 两个人必须都装 InStoreMatch.dll（店内マッチング标签修复）

这是 2026-10-04 查清的**最后一个坑**。NyanLink 的 mod 会把「店内マッチング」
这个分类的数据异步塞进游戏，但**不会刷新选曲界面底部那排分类标签**
（游戏只在进入界面时给标签栏拍一次快照），所以那一格永远不出现、也进不去
对方的房间。

`InStoreMatch.dll` 就是补这一步的小插件：检测到「店内マッチング」数据后，
用游戏自己的方式把标签栏重拍一次，并补齐滚动边界。**两个人各自都要装**，
只有一边装的话，没装的那一边照样看不到入口。

从本仓库 [最新 Release](https://github.com/isakio/maimai-instore/releases/latest) 下载
`InStoreMatch.dll`（v2.5，18432 字节 / md5 `1a94a9b6be9b03bfb274e41b0a8256b3`；
仓库里的 [`client/InStoreMatch.dll`](../client/InStoreMatch.dll) 是同一份）。
想自己编就用 `tools/build_instorematch.ps1`。放法：

```
<游戏根目录>\Mods\InStoreMatch.dll
```

验证：重启游戏后看 `MelonLoader\Logs\Latest.log`，开头应有

```
[InStoreMatch] v2.5 已加载（重拍标签栏 _tabDatas + 补滚动边界；AutoJump=False，ShowGenreCard=True，ShowRightArrow=True，ShowBackButton=True）
[InStoreMatch] 挂钩成功: reinputConnectCombineData
...（一共 7 行“挂钩成功”）
```

并且第一条招募出现后会有

```
[InStoreMatch] 重拍标签栏(...)：genre=N ... 重建后 _tabDatas=N 项
[InStoreMatch] 已放开「店内マッチング」大卡片（GetCategoryName 加零宽空格）
[InStoreMatch] 面板右键已改按真实分类数判断（本次 Update 临时借用 freedom 分支）
[InStoreMatch] 已在「店内マッチング」里放回 BACK 按钮
```

注意 v2.5 默认 **`AutoJump=False`**：招募出现时**不会**自动把你切过去（上一版会，
有点唐突）。手动过去有两种方式：

1. 选曲界面顶上的分类栏滚到最右边那一格（`店内マッチング`，蓝色图标）
2. 按「ジャンル」打开面板 → 右箭头切到最后一格

想让招募出现时**自动**切到那一格（v2.4 的行为），把 `tools/InStoreMatch.cs` 顶部的
`AutoJump` 改成 `true` 再编译即可。

**只要有 `挂钩失败` 就说明对方的游戏版本和这份 dll 不匹配**（挂不上的补丁会被跳过、
不会崩游戏，但那一格就不会出现），把日志发过来对一下版本。


## 三、操作步骤（两边各做一遍）

1. **完全关闭游戏**（不是最小化，进程要退干净）
2. 打开 `Mods\` 目录，**删掉里面所有** `WorldLink.dll` / `NyanLink.dll`（避免新旧并存）；
   换版本时也把旧的 `InStoreMatch.dll` / `WLDiag.dll` 删掉——同时存在两份会把补丁打两遍
3. 把新的 `WorldLink.dll` 和 `InStoreMatch.dll` 放进去
4. 在游戏根目录放 `WorldLink.toml`，内容照上面写
5. 启动游戏

### 三之二、★ 进 Test 模式设置基准机（最容易漏的一步）

NyanLink 整合包的说明里明确要求：「启动游戏，**在 Test 模式中像图片那样设置基准机**」。
这一步是 NyanLink 官方要求（基准机设置），照做就行。

> 更正：之前以为「分类不出现」是这一步没做导致的，2026-10-04 查清真正原因是
> 客户端标签栏没被刷新（见「二之二」）。Test 模式该设还是要设，但**光设它不够**。

进 Test 模式：**按住 `F1` 不放几秒**（segatools 里 `test=0x70`，0x70 就是 F1 键）。

进去后选「**ゲーム設定**」，把两项改成：

| 项目 | 要设成 |
| --- | --- |
| 店内マッチングの設定 | **ON** |
| グループ内基準機の設定 | **基準機** |

> 找不到这两项？就在「ゲーム設定」页里从上往下找这两个词：
> `店内マッチングの設定` 和 `グループ内基準機の設定`（NyanLink 整合包里附了截图，
> 本仓库不分发那张图）。

改完退出 Test 模式（回主界面）并**重启游戏**。两个人都要做。

### 校验 DLL 是不是对的（PowerShell）

把路径换成你自己的游戏目录：

```powershell
$dll = "D:\game\maimai\SDEZ1.70\Package\Mods\WorldLink.dll"
(Get-Item $dll).Length                                    # 必须输出 50176
(Get-FileHash $dll -Algorithm MD5).Hash                   # 必须输出 9DFA62D5CBA41DEAC0C2C74334EF8371
```

两条都对上才算过关。数字对不上就是拿错文件了 —— 两边直接用**同一个文件**
（本仓库不分发 NyanLink 的客户端 mod，请从
[NyanLink 官方 release](https://github.com/MuNET-OSS/NyanLink/releases) 下载后互相传阅）。

## 四、验证配置生效

启动游戏后看 `<游戏根目录>\MelonLoader\Logs\Latest.log`，应该出现：

```
[NyanLink] WorldLink server address: isakio.cn:20101
[NyanLink] Heartbeat: 12ms, Avg: 12ms
[NyanLink] >>> CTL_START | W.........
[NyanLink] <<< CTL_START | version=1
```

**前缀必须是 `[NyanLink]`。** 如果还是 `[WorldLink]`，说明旧 DLL 没换掉或者游戏没重启。

游戏内右下角的状态面板应该显示 `NyanLink GOOD` 和一个十几毫秒的 `PING`。

## 五、验证联机

1. 两个人都进到**选曲界面**
2. 一人在选曲界面选好歌 → 点「招募」（募集）
3. 另一人**在选曲界面**等着。分类栏最右边那一格就是「**店内マッチング**」
   （蓝色图标，`UI_CMN_TabTitle_NetworkBattle`），滚过去或者直接从右边切进去
   （装了 InStoreMatch 且 `AutoJump=True` 时会自动切过去）
4. 进去后会看到对方的招募条目（没有的话是「現在 マッチング募集はありません」，
   最多等 10 秒——mod 每 10 秒拉一次房间列表）；选中它开场

注意：那声"有人在招募"的弹窗只是**通知**，不是入口，真正加入要在选曲列表里操作。

## 六、出问题时按这个顺序查

| 现象 | 先查什么 |
| --- | --- |
| 连弹窗都看不到 | 两边 `LobbyUrl` 是否一致；游戏内状态面板是 GOOD 还是 Not Connect |
| 分类栏里没有「店内マッチング」 | `Mods\InStoreMatch.dll` 装了没；日志有没有 `[InStoreMatch] v2.5 已加载` 和 `重拍标签栏` |
| 看得到招募但加不进 | 两边 DLL 的 md5 是否一致；两边游戏版本是否一致 |
| 进去后显示「現在 マッチング募集はありません」 | 对方那边招募还在不在（招募过期/进程退了就没了）；等 10 秒再看 |
| **刚刷卡登录就弹错误、日志停在 `RestoreGhost`** | 已知的旧问题：本地存档里的 ghost 指向了没装的歌。多启动几次能躲开；根治见「七之二」 |
| 加进去后卡住 | 服务端是自研的 `nyanlinkd`（systemd），不是 docker：`ssh isakio.cn 'journalctl -u nyanlinkd -n 50 --no-pager'`，看有没有 `CTL_TCP_CONNECT` 和 `DATA_SEND` |
| 服务端不通 | `ssh isakio.cn 'systemctl is-active nyanlinkd'`；网页看板 `http://isakio.cn:20100/` |

服务端侧自测（任何能上网的机器都行）：

```bash
curl -s http://isakio.cn:20100/info     # {"relayHost":"isakio.cn","relayPort":20101}
curl -s http://isakio.cn:20100/online   # {"activeRecruits":0,"totalUsers":N}
```

## 七、登录时 `RestoreGhost` 崩（已知旧问题，不能忽略）

症状：刷卡登录后直接弹错误框，`Package\Errorlog\` 里出现新文件，内容停在

```
System.NullReferenceException
  at Process.PlInformationProcess.RestoreGhost (Int32 index)
  at Process.PlInformationProcess.UpdateUserData ()
```

原因（反汇编确认）：本体在 `RestoreGhost` 里拿 ghost 记录去查曲目，
**兜底分支查完没判空**；只要本地存档里的 ghost/段位记录指向一首没装的歌，就会崩。
AquaMai 的 `[SanitizeUserData]` 只清 `selectMusicId`，没清 ghost 列表。

这跟 InStoreMatch 无关（InStoreMatch 最早的版本出现之前就有这份崩溃记录），但**两边都可能撞上**：

1. 多启动几次（它是偶发的，取决于这次加载到哪些 ghost）
2. 关掉游戏，把 `Package\UserData\`（或 AquaMai 存用户数据的位置）**先备份**再清掉
   ghost / 段位相关文件
3. 或者把这个现象反馈给 AquaMai

## 八、一条可以忽略的报错

```
[NyanLink] ERROR Error: send failed null (0)
```

来自游戏原生网络层，出现在 `Skip Startup Network Check` 之后，不影响联机，忽略即可。
